## Overview

The Nemesis System is a living, persistent demon hierarchy that simulates an evolving power structure in the world. Each demon is a unique named character with personality, memories, emotions, rivalries, and growth. The system creates emergent stories through:

- **Offscreen demon-vs-demon battles** that run daily
- **Live combat encounters** between players and spawned nemesis demons
- **Cascading promotions** when Kizuki (ranked demons) are killed
- **Relationship-driven schemes** where demons target each other based on rivalry, ambition, and personality
- **Context-aware taunts** that reference past encounters and emotional state
- **Player intel tiers** that control how much information the player learns about events

The system is inspired by the Twelve Kizuki (Twelve Demon Moons) from the Demon Slayer anime. It is tightly integrated with the Reputation System — specifically the Demon Notoriety dimension — which modifies spawn behavior, taunt content, and behavioral overrides at runtime. The two systems are designed as peers: Nemesis owns demon identity, hierarchy, and simulation; Reputation owns the player's standing with all factions including the demon world.

**Cross-System Dependency:** The Nemesis System reads from `ReputationManager` (Reputation System) at spawn time and during the daily simulation. It never writes to `ReputationManager` directly — reputation changes flow through `WitnessEvent`s generated by combat outcomes. See [§20](#reputation-system-integration) for the full integration specification.

## Architecture

```
DemonHierarchyManager (SavedData — world-saved singleton)
├── kizukiSlots:            Map<DemonRank, UUID>          — 12 ranked moon positions
├── rankedFodder:           List<UUID>                    — unranked demon pool
├── demonDataCache:         Map<UUID, DemonTrait>         — all demon data
├── demonPacks:             Map<UUID, Set<UUID>>          — persistent pack memberships (leader -> members)
├── allKnownPlayers:        Set<UUID>                     — every player UUID ever seen; drives fodder pool target
├── worldStoryLog:          List<StoryEvent>              — bounded event log (max 200)
├── playerIntelManager:     PlayerIntelManager            — per-player intel tiers
├── battleSessionTracker:   BattleSessionTracker          — live combat tracking (transient)
├── activeWorldBattles:     Map<UUID, UUID>               — demon-vs-demon fights (transient)
└── activeAlliances:        Map<UUID, ActiveAlliance>     — short-lived coordinated assaults (transient)

ReputationManager (read-only from Nemesis perspective)
└── playerRecords:          Map<UUID, PlayerRepRecord>    — queried at spawn time
    └── demonRep (int)                                    — Demon Notoriety score
```

**Entry point:** `DemonHierarchyManager.get(ServerLevel)` — lazily initializes on first access.

**Event handler:** `NemesisSystemEvents` — subscribes to Forge events for combat, ticks, and player interactions.

## Initialization & Blueprint System

### Blueprint Loading (`BlueprintLoader`)

Blueprints are JSON files in `config/demonslayer/blueprints/` that define canonical Kizuki demons. On first load (or when individual files are missing), defaults are seeded from bundled resources.

| File Pattern | Purpose |
| --- | --- |
| `LM6.json`, `UM1.json`, etc. | Specific demon blueprints, keyed by `DemonRank.getBlueprintId()` |
| `personality_arrogant.json` | Default taunts/announcements for a personality type |
| `_defaults.json` | Global fallback taunts/announcements |

### Blueprint Schema (`DemonBlueprint`)

```json
{
  "id": "LM6",
  "name": "Kamanue",
  "title": "the Sixth Lower Moon",
  "behavior": "CALM",
  "personality": "PARANOID",
  "bda": "SLEEP",
  "quirks": ["NIGHT_STALKER", "MAGPIE", "WIND_UP"],
  "stats": { "vigor": 35, "strength": 30, "agility": 40 },
  "blood_points": 0,
  "taunts": {
    "generic": ["..."],
    "notorious_greeting": ["..."],
    "cursed_name_greeting": ["..."],
    "prey_taunt": ["..."],
    "weakling_taunt": ["..."],
    "muzan_dispatch_taunt": ["..."],
    "corps_traitor_taunt": ["..."],
    "low_health_comeback": ["..."]
  },
  "announcements": {
    "fodder_duel_win_high_diff": ["..."]
  }
}
```

> **Note:** All six notoriety-aware taunt keys are first-class fields in the blueprint schema. Blueprints that omit them fall back to personality defaults, then global defaults.

### World Initialization Flow (`initialPopulation`)

```
DemonHierarchyManager.get(level)
  └─ if (!initialized) → initialPopulation(level)
       ├─ BlueprintLoader.loadBlueprints()
       ├─ if (useCanonKizuki gamerule):
       │    for each moon rank:
       │      ├─ Look up blueprint by rank.getBlueprintId()
       │      ├─ Create DemonTrait directly (no entity needed)
       │      ├─ DemonGenerator.initializeBlueprintTrait(trait, bp, gameTime)
       │      ├─ Apply blood_points, taunts, announcements from blueprint
       │      ├─ addDemon(uuid, trait) → registers in demonDataCache + rankedFodder
       │      └─ setKizukiRank(rank, uuid) → moves from fodder to kizukiSlots
       ├─ else: generate procedural demons for each moon rank
       └─ refillDemonRoster(level) → fill fodder pool up to 20
```

> **Key design decision:** Initialization creates `DemonTrait` objects directly without spawning entities. This avoids dependency on the Forge entity capability system during world setup, which can fail silently if capabilities aren't attached yet.

### Procedural Generation (`DemonGenerator`)

For non-blueprint demons:
1. Random **Behavior** selected from all 16 archetypes
2. **Personality** chosen 75% from behavior-preferred pool, 25% fully random
3. Random name, title, territory (biome)
4. Random BDA from starter pool (Threads, Sash, Haemo, Sleep)
5. Quirk package roll (50/50): **2 strength + 1 weakness** *or* **1 strength + 2 weaknesses** (no duplicates within each pool)
6. Base stats start at (5/5/5) and apply generation-time quirk modifiers for **every** rolled quirk
7. **Intel-gathering ability** derived from behavior + personality

Procedural quirk pools:

- **Strength pool:** `HEAVY_HITTER`, `BLOOD_SIPHON`, `SHOCKWAVE_STOMP`, `VENOMOUS`, `EXECUTIONER`, `FIRE_RESISTANT`, `FROST_BLOODED`, `ARROW_PROOF`, `TENACIOUS`, `UNSHAKABLE`, `RAPID_RECOVERY`, `DEATH_DEFIANT`, `NIMBLE`, `NIGHT_STALKER`, `KEEN_Scent`, `PACK_CALLER`
- **Weakness pool:** `FEAR_OF_WATER`, `BRITTLE`, `SUNLIGHT_SICKNESS`, `FLAMMABLE_FLESH`, `PURIFIED_WEAKNESS`, `OVERCONFIDENT`, `GLASS_CANNON`, `WIND_UP`, `BLIND_RAGE`, `OBSESSIVE_HUNTER`, `SOUND_SENSITIVE`, `MAGPIE`, `EASILY_TAUNTED`

`DISHONORED` is a status/outcome quirk (humiliation/tainted outcomes), and is not procedurally rolled.

## Demon Identity — `DemonTrait`

Every demon has a complete identity profile stored in `DemonTrait` (implements `IDemonTrait`). This is the authoritative record of a demon's existence — it persists whether or not the demon is currently loaded as an entity in the world.

### Core Identity

| Field | Type | Description |
| --- | --- | --- |
| `name` | String | Short display name (e.g., "Akaza") |
| `title` | String | Epithet (e.g., "the Upper Moon Three") — can change via evolution |
| `sourceBlueprintId` | String | "procedural" or blueprint ID like "UM3" |
| `behavior` | `Behavior` | AI combat archetype (16 options) |
| `personality` | `Personality` | Dialogue/taunt tone (33 options) |

### Combat Stats

| Stat | Range | Effect |
| --- | --- | --- |
| `vigor` | 0–50 | HP pool; entity health = `10 + vigor * 5` |
| `strength` | 0–50 | Damage; entity damage = `2 + strength` |
| `agility` | 0–50 | Speed; entity speed = `0.23 + agility * 0.005` |
| `bloodPoints` | 0–∞ | Power currency; affects spawn chance, sim battle weight, Blood Battle outcomes |

### Identity Extensions

| Field | Type | Description |
| --- | --- | --- |
| `quirks` | `List<Quirk>` | 44 unique combat modifiers (offensive, defensive, environmental, sensory) |
| `bda` | `BloodDemonArts` | Assigned Blood Demon Art |
| `territory` | `ResourceLocation` | Home biome |
| `homePosition` | `BlockPos` | Used by territorial AI |
| `blueprintTaunts` | `Map<String,List<String>>` | Per-demon dialogue map from JSON, keyed by `TauntKey` constants |
| `blueprintAnnouncements` | `Map<String,List<String>>` | Per-demon announcement map from JSON |

### Temporal State

| Field | Type | Description |
| --- | --- | --- |
| `birthTime` | long | World tick when the demon was created |
| `lastBattleTime` | long | World tick of the last concluded battle session |
| `lastSeenTime` | long | World tick of last daily simulation or loaded-chunk processing |

> **Design Note — No Notoriety Cache on DemonTrait:** Demon Notoriety is a global player stat owned by `ReputationManager`. Because many demons query one player's notoriety (many-to-one), caching it per-`DemonTrait` would cause stale reads and redundant storage. Instead, demons query `ReputationManager.get(level)` once at spawn time. The result is stored on the transient `BattleSession` for the duration of that encounter — no persistent caching anywhere in `DemonTrait`.

## Hierarchy — Kizuki Slots & Fodder

### Demon Ranks (`DemonRank`)

```
FODDER → LOWLY_DEMON → DEMON → GREATER_DEMON → ELITE_DEMON
  └── (Non-moon ranks, not used by Nemesis hierarchy)

Moon Ranks (Nemesis Kizuki):
LOWER_MOON_6 (LM6) ← weakest moon
LOWER_MOON_5 (LM5)
LOWER_MOON_4 (LM4)
LOWER_MOON_3 (LM3)
LOWER_MOON_2 (LM2)
LOWER_MOON_1 (LM1)
UPPER_MOON_6 (UM6)
UPPER_MOON_5 (UM5)
UPPER_MOON_4 (UM4)
UPPER_MOON_3 (UM3)
UPPER_MOON_2 (UM2)
UPPER_MOON_1 (UM1) ← strongest moon
```

### Data Structure

- **`kizukiSlots`** (`Map<DemonRank, UUID>`) — at most 12 entries, one per moon rank
- **`rankedFodder`** (`List<UUID>`) — unranked demon pool, target size 20
- **`demonDataCache`** (`Map<UUID, DemonTrait>`) — ALL demons (both Kizuki and fodder)
- **`allKnownPlayers`** (`Set<UUID>`) — every player UUID ever seen; drives fodder pool target

### Roster Maintenance

- `refillDemonRoster()` runs daily, generating up to 5 procedural demons per call to maintain 20 fodder
- Fodder demons with ≥200 BP are eligible for Kizuki promotion via power vacuum

## Simulation Engine — Daily Tick

Every 24,000 ticks (~20 real minutes = 1 in-game day), `runDailySimulation()` executes:

```
1.  Emotion decay for all demons
2.  Growth stat daily budget reset
3.  Relationship decay (intel -3%/day, rivalry -1%/day)
4.  Build passive rivalries (adjacent ranks, personality clashes)
5.  Fodder vs Fodder battle (1 per day)
6.  Challenger vs LM6 (every 3 days)
7.  Kizuki vs Kizuki — ANY moon rank can challenge the rank above (every 9 days, 50% chance)
8.  Refill demon roster
9.  Fill ALL vacant Kizuki slots immediately (BP threshold check, loops until done)
10. Apply age-based passive growth to all demons
11. Spread rumors to online players
12. Prune old intel
13. Weekly digest (every 7 days)
```

## Offscreen Battle Resolution

Simulated battles use a deterministic TTK (Time-To-Kill) model:

```
EffectiveStats = base stats * home-field bonus * quirk modifiers * biome/time modifiers
TTK_attacker = defender_health / (attacker_damage * attacker_agility)
TTK_defender = attacker_health / (defender_damage * defender_agility)
Winner = lower TTK
```

### Quirk Effect Surface (Stat + Ability)

Quirks are applied in three layers so they are not stat-only:

1. **Generation layer** (`DemonGenerator`) - every rolled quirk applies persistent stat deltas to base vigor/strength/agility.
2. **Offscreen layer** (`DemonHierarchyManager#getEffectiveStats`) - all quirks modify effective health/damage/agility for simulated daily battles.
3. **Live combat layer** (`NemesisSystemEvents`, `NemesisAttackGoal`, `NemesisDemonEntity`) - quirks apply runtime abilities (poison procs, shockwave splash, one-time death defiance, projectile/fire mitigation, fixation/distraction behavior, ally calls, and cadence modifiers).

### Outcome Types (`SimOutcome`)

| Outcome | Condition | Result |
| --- | --- | --- |
| `DECISIVE_WIN` | Default | Loser dies, winner gains BP |
| `RETREAT` | Close fight + personality allows it | Loser survives with BP loss |
| `HUMILIATION` | Loser dealt <10% of total damage | Loser gets `DISHONORED` quirk |

### Retreat Probability by Behavior

| Behavior | Retreat Chance |
| --- | --- |
| COWARDLY, SCAVENGER, SKIRMISHER | 70% |
| STRATEGIST | 50% |
| TERRITORIAL, CALM | 40% |
| AGGRESSIVE, BERSERKER, DUELIST | 5% |
| Others | 20% |

## Battle System — Live Sessions

### `BattleSessionTracker`

Tracks real-time combat between spawned nemesis demons and players/other demons:

1. **Recording:** Each damage event creates/updates a `BattleSession`
2. **Timeout:** Sessions expire after 600 ticks (30 seconds) of no damage
3. **Finalization:** On death, flee, or timeout → derives `BattleOutcome` → writes `DemonMemory` fact
4. **Growth:** Updates `GrowthStats` with battle count, damage dealt/taken, kills

### Battle Outcome Derivation (`BattleOutcome`)

| Condition | Memory Type |
| --- | --- |
| Opponent died, demon never below 50% HP | `WON_EASILY` |
| Opponent died, demon dropped below 25% HP | `WON_CLOSE_CALL` |
| Demon died, opponent never below 50% HP | `LOST_BADLY` |
| Demon died, damage ratio <10% | `HUMILIATED` |
| Demon fled or timeout | `ESCAPED_BATTLE` |

## Growth & Progression

### `GrowthCalculator` — Stateless Utility

Called once per simulation day for each demon. Growth sources:

#### 1. Age-Based Passive Growth
- Every 7 in-game days, +1 point to the lowest stat
- Subject to daily budget (max 5 points/day) and rank cap

#### 2. Battle-Driven Growth (Primary)
- Each new battle processed grants 0–3 base points:
  - Won with high damage taken (close fight) → 3 points
  - Won easily → 1 point
  - Lost (survived) → 1 point
  - Escaped → 0 points
- Win-streak bonus: `+streak/3` (capped at 10)
- Points distributed randomly weighted toward lowest stat

#### 3. BDA Acquisition
- Requires: ≥10 battles, ≥5 wins, currently no BDA
- 20% chance per eligible check to unlock a random BDA

#### 4. Quirk Acquisition from Streaks
- 3-win streak → eligible for tier-1 quirk
- 5-win streak → tier-2
- 10-win streak → tier-3

### Stat Caps by Rank

| Rank | Stat Cap |
| --- | --- |
| Fodder/Unranked | 20 |
| Lower Moon | 35 |
| Upper Moon | 50 (hard cap) |

### Diminishing Returns
Growth effectiveness halves as a stat approaches `SOFT_CAP_THRESHOLD` (25).

## Memory System

### `DemonMemory` — Immutable Fact Records

Demons store a bounded list of up to 50 memories (most recent first). Each memory contains:
- **`MemoryType`** — categorical fact (45+ types)
- **`timestamp`** — world tick when it happened
- **`sourceEntity`** / **`targetEntity`** — optional UUIDs
- **`context`** — free-form key-value map (damage, biome, style, etc.)

### Memory Types (Grouped)

| Category | Examples |
| --- | --- |
| Combat wounds | `WOUNDED_BY_FLAME`, `WOUNDED_BY_WATER`, `WOUNDED_BY_THUNDER`, ... |
| Styles fought | `FOUGHT_FLAME_STYLE`, `FOUGHT_WATER_STYLE`, ... |
| Battle outcomes | `WON_EASILY`, `WON_CLOSE_CALL`, `LOST_BADLY`, `HUMILIATED`, `ESCAPED_BATTLE` |
| Kills | `KILLED_PLAYER`, `KILLED_KIZUKI`, `DEFEATED_KIZUKI` |
| Hierarchy | `PROMOTED`, `DEMOTED` |
| Social | `RIVALRY_STARTED`, `BETRAYED_ALLY`, `WAS_BETRAYED` |
| Survival | `SURVIVED_SUNRISE`, `NEAR_DEATH_EXPERIENCE` |
| Player fled | `ESCAPED_PLAYER` — written when the player fled a live battle session |

Fast indexes (`memoryCounts`, `lastMemoryTimes`) avoid full-list scans for common queries.

## Emotion System

### `EmotionState` — Derived Feelings

Emotions are **derived from** factual memories but **stored independently** (never re-derived on load).

### Emotion Types

| Category | Emotions | Decay/Day |
| --- | --- | --- |
| Style fears | `FEAR_FIRE`, `FEAR_WATER`, `FEAR_THUNDER`, etc. | 0.02 |
| Style hates | `HATE_FLAME_STYLE`, `HATE_WATER_STYLE`, etc. | 0.01 |
| Player emotions | `RESPECT_PLAYER`, `CONTEMPT_PLAYER`, `FEAR_PLAYER`, `HATE_PLAYER` | 0.005–0.02 |
| Demon emotions | `RIVALRY_GRUDGE` | 0.005 |
| General states | `BLOODLUST`, `DESPERATION` | 0.03–0.05 |

Each emotion has:
- **Intensity** (0–cap, usually 1.0)
- **Base gain rate** per triggering event
- **Decay rate** per in-game day
- **Last updated** timestamp

Personality modifies gain rates (e.g., bloodthirsty demons gain `BLOODLUST` faster).

## Relationship System

### `DemonRelationship` — Directed Graphs

Each demon tracks relationships toward other demons via `Map<UUID, DemonRelationship>`:

| Field | Range | Description |
| --- | --- | --- |
| `rivalryIntensity` | 0–1.0 | How much they want to fight this demon |
| `allianceStrength` | -1.0–1.0 | Positive = allied, negative = hostile |
| `encounterCount` | 0–∞ | Times they've fought |
| `lastConflictTime` | tick | When they last fought |
| `intelOnTarget` | 0–1.0 | How well they know this demon's abilities |

### Relationship Drivers

**Passive (daily):**
- Adjacent Kizuki ranks build rivalry (+0.03/day if ambitious/arrogant)
- Clashing personalities build mutual rivalry (+0.02/day)

**Active (per battle):**
- Rivalry: +0.15 for close fights, +0.08 otherwise
- Intel: +0.15 + base intel ability * 0.10

**Decay (daily):**
- Intel: -3% per day
- Rivalry: -1% per day

### Personality Clashes
These personality pairs naturally build rivalry:
- HONOR_BOUND vs DECEPTIVE/MANIPULATIVE
- COCKY vs RUTHLESS
- ARROGANT vs ARROGANT
- COMMANDING vs COMMANDING
- DEVOTED vs MOCKING

## Pack & Alliance System

The Nemesis social layer now supports two coordinated-combat structures:

- **Packs (persistent):** stored in `demonPacks` and rebuilt/maintained during daily simulation.
- **Alliances (temporary):** stored in transient `activeAlliances` with timeouts, used for active fights.

### Pack Formation

During `runDailySimulation()`:

1. Existing packs are pruned (dead/invalid members removed).
2. Eligible leaders are selected strictly by behavior/personality profile.
3. Among eligible leaders, the strongest demon is chosen first (`bloodPoints + stat score`).
4. Compatible demons are added up to a dynamic cap based on leader profile + strength.
5. Soft-limit maintenance rolls can reject additional members as size grows.
6. Relationship affinity is reinforced (`allianceStrength` grows slightly).

Packs persist through world saves in `demonPacks` NBT (`leader UUID -> member UUID list`).

### Compatibility Rules

Compatibility is scored by combining:

- **Behavior affinity** (`OVERLORD/LOYALIST/BODYGUARD` synergy, tactical synergy, volatile clashes).
- **Personality affinity** (same-personality bonus, known clash penalty, leadership/protective combos).
- **Relationship state** (`allianceStrength` positive, `rivalryIntensity` negative, `intelOnTarget` minor bonus).
- **Join propensity bonus** (candidate behavior/personality incl. LOYALIST/BODYGUARD bias).
- **Mutual enemy bonus** (temporary alliances only).

Every behavior and personality is explicitly mapped in at least one of:

- cooperation bias,
- join bias,
- leader eligibility,
- dynamic cap modifiers,
- or soft-limit leader-factor modifiers.

Only demons above threshold are allowed to join packs or tactical alliances.

#### Exact Compatibility Formula

`compatibilityScore` is clamped to `[-1.0, 1.0]`:

```text
score = 0.25
      + behaviorAffinity(A.behavior, B.behavior)
      + personalityAffinity(A.personality, B.personality)
      + packJoinAffinityBonus(B)
      + ((behaviorJoinBias(A.behavior) + personalityJoinBias(A.personality)) * 0.35)
      + (A->B allianceStrength * 0.35)
      - (A->B rivalryIntensity * 0.45)
      + (A->B intelOnTarget * 0.05)
      + (B->A allianceStrength * 0.20)
      - (B->A rivalryIntensity * 0.30)
```

For temporary alliances, an additional `mutualEnemyBonus` is added during ally selection/ranking.

### Leader Eligibility (Behavior + Personality)

Leaders must pass **eligibility first**, then strongest eligible is chosen.

- **Behavior-eligible leaders:** `OVERLORD`, `LOYALIST`, `STRATEGIST`, `TERRITORIAL`
- **Personality-eligible leaders (fallback):** `COMMANDING`, `CALCULATING`, `DECEPTIVE`, `MANIPULATIVE`

Strength then breaks ties and ordering:

- `strengthScore = bloodPoints + (vigor + strength + agility) * 12`
- Pack creation repeatedly picks the **strongest currently unassigned eligible leader**.

### Behavior/Personality Relationship Effects

Key behavior interactions used by compatibility scoring:

- **Behavior affinity constants**
  - Same behavior: `+0.35`
  - Tactical pair (`STRATEGIST`/`TRICKSTER`/`CALM`/`TERRITORIAL`): `+0.18`
  - Command pair (`OVERLORD`/`LOYALIST`/`BODYGUARD`): `+0.22`
  - `OVERLORD` + `LOYALIST` special pair: `+0.20`
  - `BERSERKER` vs `COWARDLY`: `-0.30`
  - Mixed volatile pair (`BERSERKER`/`COWARDLY`/`SCAVENGER`): `-0.12`

Behavior cooperation base examples (from exhaustive per-behavior map):

- High cohesion: `LOYALIST +0.14`, `BODYGUARD +0.12`, `OVERLORD +0.10`, `STRATEGIST +0.08`
- Stable/neutral: `CALM +0.06`, `STALWART +0.05`, `TERRITORIAL +0.04`, `TRICKSTER +0.03`, `SKIRMISHER +0.02`
- Friction-prone: `AGGRESSIVE -0.01`, `AMBITIOUS -0.03`, `SADIST -0.04`, `SCAVENGER -0.06`, `DUELIST -0.08`, `COWARDLY -0.10`, `BERSERKER -0.12`

Key personality interactions:

- **Personality affinity constants**
  - Same personality: `+0.20`
  - Known clash pair (from `arePersonalitiesClashing`): `-0.25`
  - `DEVOTED` + `COMMANDING`: `+0.16`
  - `PROTECTIVE` + `CAUTIOUS`: `+0.10`
  - `BLOODTHIRSTY` + `CALCULATING`: `-0.12`
  - `JESTING` + `MELODRAMATIC`: `+0.08`
  - `STOIC` + `WHINING`: `-0.10`

Personality cohesion base (exhaustive per-personality map):

- Strong cohesion: `COMMANDING`, `DEVOTED`, `PROTECTIVE`, `CALCULATING`, `PATIENT`, `STOIC`, `PHILOSOPHICAL` (`+0.10`)
- Tactical/social cohesion: `OBSERVANT`, `CAUTIOUS`, `DECEPTIVE`, `MANIPULATIVE`, `OPPORTUNISTIC`, `FANATICAL` (`+0.06`)
- Ego/friction leaning: `COCKY`, `RUTHLESS`, `ARROGANT`, `MOCKING`, `CRUEL`, `JESTING`, `MELODRAMATIC` (`-0.02`)
- High-friction set: `BLOODTHIRSTY`, `FRENZIED`, `GLUTTONOUS`, `PARANOID`, `NERVOUS`, `WHINING`, `INSECURE`, `GRIEVING`, `WEARY`, `LAZY`, `HONOR_BOUND`, `YANDERE` (`-0.05`)

Join-propensity (candidate-side) bonus:

- **Behavior join bonus**
  - `LOYALIST`: `+0.22`
  - `BODYGUARD`: `+0.20`
  - `OVERLORD`, `STRATEGIST`, `STALWART`, `CALM`: `+0.08`
  - `TERRITORIAL`, `SKIRMISHER`, `TRICKSTER`, `AGGRESSIVE`: `+0.02`
  - `AMBITIOUS`, `SCAVENGER`: `-0.02`
  - `SADIST`: `-0.04`
  - `DUELIST`: `-0.05`
  - `COWARDLY`, `BERSERKER`: `-0.06`
- **Personality join bonus**
  - `DEVOTED`, `PROTECTIVE`, `FANATICAL`: `+0.12`
  - `CALCULATING`, `DECEPTIVE`, `MANIPULATIVE`, `CAUTIOUS`, `PATIENT`, `STOIC`, `OBSERVANT`: `+0.06`
  - `COMMANDING`, `PHILOSOPHICAL`, `OPPORTUNISTIC`, `WEARY`: `+0.02`
  - `COCKY`, `ARROGANT`, `RUTHLESS`, `JESTING`, `MELODRAMATIC`, `CRUEL`, `GLUTTONOUS`, `GRIEVING`, `LAZY`, `YANDERE`: `-0.02`
  - `HONOR_BOUND`, `INSECURE`, `WHINING`, `NERVOUS`, `PARANOID`, `BLOODTHIRSTY`, `FRENZIED`, `MOCKING`: `-0.05`

Both systems are combined with relationship metrics (`allianceStrength`, `rivalryIntensity`, `intelOnTarget`) to produce final compatibility.

### Personality Cohesion vs Clash

Not all personalities naturally cohere. Cohesion mostly comes from:

- identity match (same personality),
- command/support combinations,
- positive prior relationship state.

Clashes are explicit and persistent pressure points:

- `HONOR_BOUND` vs `DECEPTIVE`/`MANIPULATIVE`
- `COCKY` vs `RUTHLESS`
- `ARROGANT` vs `ARROGANT`
- `COMMANDING` vs `COMMANDING`
- `DEVOTED` vs `MOCKING`
- `STOIC` vs `WHINING`
- `CALCULATING` vs `FRENZIED`
- `PROTECTIVE` vs `CRUEL`
- `PATIENT` vs `BLOODTHIRSTY`
- `CAUTIOUS` vs `BLOODTHIRSTY`

### Dynamic Caps + Soft Limits

Both pack size and allies-per-call are dynamic:

- **Base cap** from leader behavior/personality.
- **Strength bonus** from `strengthScore`.
- **Hard ceiling** (`MAX_PACK_SIZE_HARD`, `MAX_ALLIES_PER_CALL_HARD`).
- **Soft maintenance roll** for each extra member/ally beyond the core pair.

Result: large groups are possible for very strong/commanding leaders, but progressively harder to sustain.

#### Pack Cap (`getSoftLimitedPackCap`)

- **Behavior base**
  - `OVERLORD`: `5`
  - `LOYALIST`: `4`
  - `STRATEGIST`, `TERRITORIAL`, `STALWART`: `3`
  - `BODYGUARD`, `CALM`, `SKIRMISHER`, `TRICKSTER`, `AGGRESSIVE`, `AMBITIOUS`: `2`
  - `BERSERKER`, `DUELIST`, `COWARDLY`, `SCAVENGER`, `SADIST`: `1`
- **Personality modifier**
  - `COMMANDING`, `FANATICAL`, `PROTECTIVE`, `CALCULATING`: `+1`
  - `LAZY`, `WHINING`, `INSECURE`, `PARANOID`, `NERVOUS`: `-1`
  - others: `0`
- **Strength bonus**: `min(2, strengthScore / 900)`
- **Clamp**: `[2, MAX_PACK_SIZE_HARD]`

#### Ally-Call Cap (`getSoftLimitedAllyCallCap`)

- **Behavior base**
  - `OVERLORD`: `3`
  - `LOYALIST`, `STRATEGIST`, `TERRITORIAL`, `BODYGUARD`: `2`
  - `STALWART`, `CALM`, `SKIRMISHER`, `TRICKSTER`, `AGGRESSIVE`, `AMBITIOUS`: `1`
  - `BERSERKER`, `DUELIST`, `COWARDLY`, `SCAVENGER`, `SADIST`: `0`
- **Personality modifier**
  - `COMMANDING`, `FANATICAL`, `PROTECTIVE`, `DECEPTIVE`, `MANIPULATIVE`: `+1`
  - `HONOR_BOUND`, `LAZY`, `WHINING`, `INSECURE`: `-1`
  - others: `0`
- **Strength bonus**: `min(1, strengthScore / 1200)`
- **Clamp**: `[1, MAX_ALLIES_PER_CALL_HARD]`, then min with caller-requested value

#### Soft-Maintenance Roll (`passesSoftMaintenanceRoll`)

- No roll for projected size `<= 2` (core pair always allowed).
- For size `> 2`, acceptance chance:

```text
chance = 0.86
       - ((projectedSize - 2) * pressure)
       + strengthFactor
       + leaderFactor
```

- `pressure = 0.16` for packs, `0.22` for temporary alliances
- `strengthFactor = min(0.35, strengthScore / 2600.0)`
- `leaderFactor`
  - behavior factors:
    - `OVERLORD`, `LOYALIST`: `+0.16`
    - `BODYGUARD`, `STRATEGIST`, `TERRITORIAL`, `STALWART`: `+0.08`
    - `CALM`, `SKIRMISHER`, `TRICKSTER`: `+0.03`
    - `AGGRESSIVE`, `AMBITIOUS`, `SADIST`: `-0.02`
    - `COWARDLY`, `SCAVENGER`, `BERSERKER`, `DUELIST`: `-0.08`
  - personality factors:
    - `COMMANDING`, `FANATICAL`, `PROTECTIVE`, `CALCULATING`: `+0.07`
    - `DEVOTED`, `STOIC`, `PATIENT`, `OBSERVANT`: `+0.04`
    - `DECEPTIVE`, `MANIPULATIVE`, `OPPORTUNISTIC`: `+0.02`
    - `WHINING`, `INSECURE`, `LAZY`, `NERVOUS`, `PARANOID`: `-0.05`
    - `BLOODTHIRSTY`, `FRENZIED`, `ARROGANT`, `COCKY`, `CRUEL`, `YANDERE`: `-0.03`
    - others: `0.0`
- Final chance is clamped to `[0.20, 0.95]`

### Tactical Alliances

`tryMobilizeAlliesForFight(...)` is used in three paths:

- **Reactive combat:** when a `NemesisDemonEntity` is attacked (`LivingHurtEvent`).
- **Hunter dispatch:** when a hunter spawn succeeds against a player.
- **World battles:** when rival demons are spawned for demon-vs-demon fights.

Behavior:

- Selects compatible allies from the leader's pack first, then social-compatible candidates.
- Never uses already loaded allies; loaded demons are treated as busy and skipped.
- Spawns allies by UUID through hierarchy data only when they are not currently loaded.
- Sets ally targets to the same player/demon target as the leader.
- Creates a short-lived `ActiveAlliance` entry (auto-expires on server tick).
- Applies a mutual-enemy bonus so alliances are more likely when both demons already oppose the same target.

#### Mutual Enemy Bonus (`mutualEnemyBonus`)

- If both demons have rivalry `> 0.22` against the same target: `+0.16`
- If both have hostile allianceStrength `< -0.10` against that target: `+0.08`
- If target is player and both have `HATE_PLAYER > 0.35`: `+0.10`
- Total bonus clamped to `[0.0, 0.35]`

### Expiration & Cleanup

- Alliances are periodically pruned by `tickSocialAlliances(currentTime)`.
- Dead/removed demons are scrubbed from `demonPacks` and `activeAlliances` in `killDemon(...)`.

## Hunter Spawning

Every 40 ticks (~2 seconds), `trySpawnHunterForPlayer()` runs for each online player:

### Candidate Selection
A demon is a candidate hunter if ANY of:
- Its territory matches the player's current biome
- It has a relationship with the player (rivalry >0.15 or encounter count >0)
- It has strong emotions toward the player (HATE_PLAYER >0.3 or RIVALRY_GRUDGE >0.3)

### Spawn Chance Formula

```
finalChance = baseChance × personalityMod × powerDiffMod × relationshipMod × difficultyMod
```

| Factor | Computation |
| --- | --- |
| `baseChance` | `bloodPoints / 5000` |
| `personalityMod` | 0.5× (cowardly) to 2.1× (aggressive + bloodthirsty) |
| `powerDiffMod` | 0.2× (much weaker) to 1.25× (much stronger) |
| `relationshipMod` | 1.0 + rivalry * 0.8 + hate * 0.5 |
| `difficultyMod` | 0× (peaceful) to 1.3× (hard) |

Capped at 95%. Only spawns if the demon isn't already loaded in the world.

## World Battles (Demon vs Demon)

Every ~5 minutes (6000 ticks), there's a 15% chance to attempt spawning a demon-vs-demon fight:

### Selection
1. Find the pair with highest mutual rivalry (minimum 0.3)
2. Fallback: random fodder pair

### Spawning
- Both demons spawn 40–80 blocks from a random online player
- They target each other instead of the player
- Players can witness and intervene

### Conclusion
When one dies:
- Winner gets memories, growth, BP transfer
- Loser is killed, power vacuum handled if Kizuki
- All online players get `CONFIRMED` intel on the event
- Broadcast announcement to server

## Blood Battles (Demon-Path Player vs Demon)

When a demon-path player attacks a higher-ranked nemesis demon:

### Initiation
- Auto-triggered when demon player BP < nemesis demon BP
- Tracks the `challenger` (player UUID) and `defender` (demon UUID)

### Interference Tracking
Any entity that damages the defender (other than the challenger) is recorded as an interferer.

### Conclusion (`handleBloodBattleConclusion`)

**Pure Victory (no interferers):**
- Player gains 100% of defender's BP
- Player claims the defender's Kizuki rank
- Dishonor is cleansed

**Tainted Victory (interferers present):**
- Player gains 50% of defender's BP
- Player claims the rank but is marked `DISHONORED`
- Dishonored status makes them a prime target for other demons

## Power Vacuum & Cascading Promotions

When a Kizuki demon is killed, `handlePowerVacuum()` triggers:

```
Example: UM4 dies
  → Find next occupied rank below: UM5 has a demon
    → UM5 demon promotes to UM4 (cascade)
  → UM5 is now vacant, find next occupied below: UM6 has a demon
    → UM6 demon promotes to UM5 (cascade)
  → UM6 is now vacant, find next occupied below: LM1 has a demon
    → LM1 demon promotes to UM6 (cascade — crosses the Upper/Lower boundary!)
  → LM1 is now vacant, find next occupied below: LM2 has a demon
    → LM2 demon promotes to LM1 (cascade)
  ...continues cascading down...
  → LM6 is now vacant, no Kizuki below
    → Top fodder with ≥200 BP fills LM6
      → If no qualifying fodder, slot stays empty (filled next daily sim)
```

The cascade **skips empty slots** — if UM5 were also vacant, the system would find the next occupied rank below (e.g., UM6 or LM1) and promote directly.

**Cascading promotions enforce BP thresholds.** If the demon below a vacant slot doesn't meet the BP requirement for that rank, the cascade stops and the slot is left empty. This prevents weak Lower Moon demons from being blindly pulled into Upper Moon ranks just because of a vacancy. The `fillVacantKizukiSlots` daily pass will fill the slot later once a qualifying demon exists.

Each promoted demon receives a `PROMOTED` memory and a story event is logged.

### Vacancy Filling (Daily — Immediate)

The daily simulation runs `fillVacantKizukiSlots()`, which fills **ALL** vacant slots immediately in a single pass. It loops until no more promotions are possible:

- Walks from LM6 up to UM1 each iteration
- **LM6**: If vacant, promotes the strongest fodder with ≥200 BP directly
- **LM5–UM1**: If vacant and the rank directly below is occupied, checks if the occupant meets the BP threshold for the target rank. If so, promotes them and cascades a power vacuum for the now-empty lower slot.
- Repeats the full pass until nothing changes — this means a single daily sim can fill multiple vacancies in one go.

### BP Thresholds for Vacancy Promotion

Lower Moons are close in power — a uniform, low threshold represents their similar strength. Upper Moons have dramatically higher thresholds, representing the canonical power gap.

| Target Rank | BP Required |
| --- | --- |
| Lower Moon 6 | 200 |
| Lower Moon 5 | 200 |
| Lower Moon 4 | 200 |
| Lower Moon 3 | 200 |
| Lower Moon 2 | 200 |
| Lower Moon 1 | 200 |
| Upper Moon 6 | 450 |
| Upper Moon 5 | 650 |
| Upper Moon 4 | 900 |
| Upper Moon 3 | 1200 |
| Upper Moon 2 | 1600 |
| Upper Moon 1 | 2000 |

Non-moon ranks cannot be promoted into via this system (`Integer.MAX_VALUE` threshold).

This means: if all Lower Moon slots are empty and there are 6 fodder demons with ≥200 BP, they will ALL be filled in a single daily simulation. However, Upper Moon slots require significantly more BP — a demon at LM1 needs 450 BP to be promoted to UM6.

### Debug Logging

The Nemesis system includes comprehensive debug logging with the prefix `[NEMESIS DEBUG]`. All major events are logged to the console:

**Daily Simulation Events:**
- Daily simulation start/end with day counter
- Emotion decay and growth budget reset
- Relationship decay and rivalry building
- Battle simulation phases (Fodder vs Fodder, Challenger vs Kizuki, Kizuki vs Kizuki)
- Roster refill operations
- Growth application
- Rumor spreading and weekly digest delivery

**Combat Events:**
- Battle session damage tracking with HP percentages
- Blood Battle initiation with participant BP comparison
- Battle interference detection
- Combat outcomes (retreat, decisive victory, etc.)

**Hierarchy Changes:**
- Rank assignments and changes with before/after status
- Power vacuum cascading promotions with detailed progression
- Demon deaths with rank information
- Fodder promotions to Kizuki with BP thresholds

**Story Events:**
- All story events logged with full details when recorded
- Blood Battle conclusions with victory type and rewards
