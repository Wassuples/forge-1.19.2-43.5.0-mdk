NEMESIS SYSTEM – COMPLETION TODO (Forge 1.19.2 mod)
===============================================

Scope
-----
This file tracks remaining work needed to complete the Nemesis System (Shadow of War-inspired) in this mod.
It intentionally avoids “integration details” (UI/networking specifics, etc.) and focuses on system requirements,
data models, and core behavior.

Top priorities (core architecture)
---------------------------------
[ ] 1) Memory model: FACTS vs FEELINGS
    - Goal: separate “what happened” from “how the demon feels about it”.
    - Facts:
        - Keep array/list of recent events (bounded, recent-first).
        - Each fact entry should include type + timestamp + (optional) source/target/context.
    - Feelings:
        - EmotionType enum separate from MemoryType.
        - Store intensity (float) + lastUpdatedTime per emotion.
        - Allow personality/behavior traits to affect:
            - probability to develop fear vs hate
            - rate of intensity gain per exposure
            - decay/forget rate (optional)
    - RULE: MemoryType should be factual; do not encode feelings as MemoryType going forward.

[ ] 2) Formal trigger/router pipeline
    - Goal: a single “routing layer” that converts gameplay or simulation outcomes into:
        gameplay event -> fact memory update -> feelings update -> taunt/announcement selection -> story logging
    - Responsibilities:
        - detect events (wound type, style used, escape/retreat, near-death, humiliation, etc.)
        - append fact memories (bounded)
        - update feelings probabilistically + intensity
        - choose taunt keys (and optionally announcement keys) deterministically from conditions

[ ] 3) Relationship models (player nemesis + demon rivals)
    - Per-player relationship (demon -> player):
        - hate/fear/respect (intensity)
        - lastBattleTime / lastSeenTime / lastTauntTime
        - encounter counts, kills/deaths, escapes, humiliations
    - Per-demon rivalry model (demon -> demon):
        - rivalry intensity / grudge reasons
        - alliances (optional) / interference tracking
        - lastConflictTime

Stability + design warnings (loopholes to avoid)
-----------------------------------------------
- Avoid exploding MemoryType into hundreds of entries; use context fields for details.
- Without battle sessionization, memory will become noisy and taunts will spam.
- Persist emotion intensities; don’t re-roll them on load (nondeterminism).
- Ensure all offscreen simulation writes the SAME kind of events as on-screen gameplay.
- Use a consistent time source (overworld gameTime) for all timestamps.
- Add diminishing returns / caps to growth to prevent unstoppable demons.
